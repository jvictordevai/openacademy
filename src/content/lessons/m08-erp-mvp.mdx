## TL;DR

Dashboard mostra dado. **ERP cria operação**. Diferença: dashboard lê, ERP escreve. Em 4 sprints você sai do "olho no número" pra "sistema da empresa funcionando".

## Por que evoluir, e não construir do zero

Empresário típico tenta comprar ERP grande (TOTVS, Senior, Bling) e:
- Implementação leva 6-12 meses
- Customização vira hostage do fornecedor
- 60% das features que pagou nunca usa
- Time resiste porque é caro mudar

**Outra estratégia**: começar pelo dashboard (que você já construiu na lição [m06-build-dashboard](/licoes/m06-build-dashboard)) e **evoluir módulo a módulo**.

## Stack do ERP MVP

| Camada | Ferramenta | Por quê |
|---|---|---|
| **Frontend + agente** | Lovable | Você descreve, ele constrói |
| **Banco de dados** | Supabase (Postgres) | RLS, auth, realtime, backup PITR |
| **Automação** | n8n | NF-e, boleto, email, integrações |
| **Segurança** | Aikido | Scan contínuo do código + cloud |
| **Pagamentos** | Stripe (B2B) ou Asaas/Cobre Fácil (boleto BR) | API direta |
| **NF-e** | NFE.io ou Plug Notas | API + SEFAZ |

Custo total mensal (operação real PME): **~US$ 80-150/mês**. Compare com TOTVS R$ 8-15k/mês.

## 5 módulos · 4 sprints

### Sprint 1 (2 semanas) — Vendas

Reaproveita o dashboard que já existe + adiciona **escrita**:

- Tela de cadastro de cliente (com validação CNPJ)
- Tela de criação de pedido (com cálculo de margem em tempo real)
- Tela de gestão de pipeline (Kanban arrastável: lead → qualif → proposta → fechado)
- Comissão calculada automática por vendedor
- Aprovações de desconto acima de X% precisa OK do gestor

**Tabelas Supabase**:
```sql
clientes (id, razao_social, cnpj, segmento, vendedor_id, limite_credito, status)
pedidos (id, cliente_id, vendedor_id, data, status, valor_total, custo_total)
pedido_itens (id, pedido_id, sku, qtd, preco_unit, desconto_pct)
oportunidades (id, cliente_id, vendedor_id, etapa, valor_estimado, prob, data_prev)
```

**RLS crítico**: vendedor só vê seus clientes/pedidos. Gerente vê tudo da região.

### Sprint 2 (2 semanas) — Estoque + Compras

- Tela de cadastro de produto (SKU, custo médio, fornecedor, lead time)
- Movimentação de estoque (entrada por NF de compra · saída por venda)
- Curva ABC automática (top 20% SKUs = X% da receita)
- Ponto de pedido (saldo + lead time + giro)
- Sugestão de compra agrupada por fornecedor

**Tabelas**:
```sql
produtos (id, sku, descricao, categoria, custo_medio, fornecedor_id, ponto_pedido)
estoque (id, sku, saldo, ultimo_custo, ultima_movimentacao)
estoque_movimentos (id, sku, tipo, qtd, custo_unit, origem, data, usuario_id)
ordens_compra (id, fornecedor_id, status, valor_total, prev_entrega)
oc_itens (id, oc_id, sku, qtd, preco_neg)
```

**Automação n8n**: quando saldo bate ponto de pedido, criar OC rascunho automaticamente e notificar compras no Slack.

### Sprint 3 (2 semanas) — Financeiro

Reaproveita a planilha financeira como ponto de partida. Adiciona:

- Contas a receber com aging automático
- Régua de cobrança (D-3 lembrete · D+1 vencido · D+7 negativação)
- Conciliação bancária semi-automática (importa OFX/CSV)
- Fluxo de caixa projetado 13 semanas (rolling)
- Centro de custo por categoria de despesa

**Tabelas**:
```sql
contas_receber (id, pedido_id, cliente_id, valor, vencimento, pago_em, status)
contas_pagar (id, fornecedor_id, categoria, valor, vencimento, pago_em, status)
movimentos_bancarios (id, conta_id, data, valor, tipo, conciliado_com)
contas_bancarias (id, banco, agencia, conta, saldo_atual)
```

**Automação n8n**:
- Boleto gerado via Asaas/Cobre Fácil quando pedido fatura
- PIX dinâmico opcional
- Email D-3, D+1, D+7 personalizado

### Sprint 4 (1 semana) — NF-e + Cobrança + Permissões

- Emissão NF-e via NFE.io ou Plug Notas (CFOP/CST baseado no perfil do cliente)
- XML armazenado no Supabase Storage
- Cobrança automática via boleto + PIX (Asaas, Cobre Fácil, Mercado Pago)
- Permissões granulares por usuário (Admin, Gerente, Vendedor, Compras, Financeiro)
- Audit log de quem alterou o quê

**Tabelas**:
```sql
notas_fiscais (id, pedido_id, chave_acesso, status_sefaz, xml_url, valor_total)
usuarios (id, email, role, regiao, ativo)
permissoes (role, recurso, acoes)
audit_log (id, usuario_id, acao, entidade, data, payload_old, payload_new)
```

## Métricas pra acompanhar evolução

| Sprint | Métrica de sucesso |
|---|---|
| Sprint 1 | 100% dos pedidos novos entram pelo sistema (não Excel) |
| Sprint 2 | Saldo do sistema bate com contagem física com erro &lt; 2% |
| Sprint 3 | Aging de contas vencidas cai 30% em 60 dias |
| Sprint 4 | NF emitida em &lt; 3 min após faturamento (vs 15 min manual) |

## Checklist de produção (antes de soltar pro time)

- [ ] Supabase Pro com PITR ativado
- [ ] Backup diário externo em S3/Backblaze (não dependa só do Supabase)
- [ ] Aikido escaneando código + cloud + container
- [ ] Custom domain configurado com SSL
- [ ] Aprovação humana em ações irreversíveis (cancelar pedido, negativar cliente)
- [ ] Audit log de quem alterou o quê
- [ ] Treinamento do time (mínimo 2 sessões de 1h)
- [ ] Plano de rollback se der ruim
- [ ] Suporte de contingência (você ou alguém de confiança disponível por 2 semanas pós-go-live)

R$ ~600/mês pra rodar ERP da PME, vs R$ 8-15k de ERP tradicional. Diferença de **20-25x** com mais flexibilidade.

## Quando NÃO seguir esse caminho

- Indústria altamente regulada (farmácia, alimentício com rastreabilidade)
- Operação fiscal complexa (transferência interestadual com substituição tributária, ICMS-ST)
- Volume gigante (1M+ pedidos/mês)
- Compliance audit obrigatório (SOC 2, ISO 27001 do dia 1)

Para 80% das PMEs brasileiras, o stack aqui resolve.
